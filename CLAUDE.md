# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

**WeCare** — a German/Austrian-market digital health platform for medical cannabis, built **problem-first** (Sleep, Pain, Stress & Anxiety, Migraine). The doctor / prescription / pharmacy layer is required but sits *behind* the assessment flow, never in front of it.

This codebase was repurposed from an unrelated Figma Make export ("Visualize Code", an hours-tracking demo). That demo's code is being stripped out phase by phase; its *engineering substrate* (Vite + React + Tailwind v4 + shadcn/ui) is being kept and reskinned. The rebuild spec lives at `../Downloads/WeCare_CLI_Implementation_Prompt.md` — it is the source of truth for scope, IA, copy rules, and the design system.

Git repo (initialised Aug 2026). **Trunk is `main`** (it holds the real history; `master` is a stale initial-commit-only branch — ignore it). Active feature work is on `audit-fixes` (ahead of `main`, clean fast-forward). Put feature work on a branch and only commit / push when explicitly asked.

## Hard rules (from the spec — do not violate)

- No leaf/smoke/dispensary imagery or recreational language anywhere.
- Homepage and problem pages lead with the **problem**, never "prescription" / "treatment". The medical layer appears *after* the assessment as "medical review" / "prescription if medically appropriate" — never guaranteed.
- Never imply every user gets a prescription.
- Primary nav: **Sleep · Pain · Stress & Anxiety · Migraine** + (right) Login · Start Assessment. **No "Shop" / "Products" / "Flowers" / "Vapes" in primary nav.** **"How It Works" and "FAQ" were deliberately removed from `PRIMARY_NAV` (owner decision, Aug 2026) — do NOT re-add them.** How-It-Works is a homepage section (now just *before* the final CTA), and `/how-it-works` **redirects** to it (`/#how-it-works`; `ScrollToHash` in `RootLayout` does the scroll). The `/faq` page **has real content** (`src/pages/FaqPage.tsx`, `faq` i18n namespace, categorised service FAQ) but is linked only from the footer, not the primary nav. This intentionally overrides the spec's §17 nav list.
- The user-facing product layer is the **5 named Solutions** (abstract wellness names), never strain/format names up front. A **new** user (assessment q5 = "No, I am new") is **never** led with the stronger (higher-THC) option regardless of severity — `gentleFirst` wins, and the result-page nudge frames oil as the controlled starting format before flower/vape.
- Every new or touched string ships in **both** DE and EN via react-i18next, including dynamic content. Variables go *inside* translation strings, not concatenated around them.

## Architecture

### Styling & tokens — `src/styles/`  (WECARE BRAND BOOK 2026)
- **`index.css` is the whole design system** — it imports `fonts.css`, imports Tailwind, then holds `@theme static` (brand primitives), `:root` (semantic layer, `color-scheme: light` — light-only, dark mode was removed Sept 2026) and `@layer base`. `theme.css` / `tailwind.css` no longer exist.
- **Color** (brand book): Light Azure `#f9fdfe` · **Azure `#218390`** (primary — the printed `#2d190e` is a typo) · **Dark Azure `#0d444b`** · Light Green `#e8f4ed`. Exposed as: `petrol-*` = the Azure teal ramp (brand / trust / medical UI + CTA), `sage-*` = the Light Green ramp (secondary / progress / "answered"), `danger-*` = a functional error red **only** (not a brand colour). Brand-name aliases: `--color-azure`, `--color-dark-azure`, `--color-light-azure`, `--color-light-green`. There is **no warm/amber accent** — the brand colour is the CTA (`--cta` = Azure, `--cta-hover` = Dark Azure).
- `:root` maps shadcn's `--primary`/`--card`/`--muted`/… onto the palette so vendored `ui/*` inherit it. `@theme inline` bridges to utilities.
- **Fonts** (`fonts.css`): `--wc-font-sans` = **Figtree** (body, loaded from Google Fonts) · `--wc-font-display` = **Schibsted Grotesk → Figtree** (headings; both OFL, from Google Fonts — Schibsted Grotesk is the free stand-in for Bloomwell's commercial *Gellix*) · `--wc-font-accent` = **Batangas → Figtree** (accents; Batangas is commercial, stack-loaded) · `--wc-font-data` = system **monospace** (verified data only — COA values, batch numbers, prices, IDs). Utilities: `font-sans` / `font-display` / `font-accent` / `font-mono`. Eyebrows are Figtree `font-semibold uppercase tracking-[0.16em]`, not mono. (Was Inter + TT Hoves through Aug 2026; swapped to Figtree + Schibsted Grotesk to echo the Bloomwell reference type pairing without licensing Gellix.)
- **Logo**: `src/components/brand/Logo.tsx` — `<Logo>` (full lockup image, size by height) and `<LogoMark>` (square mark image); `inverse` prop switches to the white artwork on dark surfaces. Uses the official PNGs in `src/assets/logos/` (`wecare-lockup-*` / `wecare-mark-*`, trimmed from `black ver.png` / `White ver.png`).
- **Liquid-glass + blue-gradient design language** (the "We Care" refinement, on top of the brand palette):
  - `<body>` paints a soft `--page-gradient` (sky → white → mint), fixed. `GradientBackdrop` (mounted in `RootLayout`) adds blurred colour orbs behind everything.
  - `.glass` / `.glass-strong` / `.glass-hover` (in `@layer components`, index.css) = frosted translucent surface + backdrop-blur + luminous border + soft shadow. Use on calm/marketing surfaces (cards, nav, panels); **keep forms, the COA table and the assessment options solid** for legibility. `.glass-strong` (higher opacity) for data panels (cart, checkout summary, question card).
  - `.image-glow` = radial "held" glow behind a floating product/hero image; pair with a `drop-shadow` on the `<img>`.
  - `--radius` = 20px; buttons are full pills; the `cta` button variant is a soft Azure→cyan gradient (`--cta-gradient`) with glow; `outline` buttons are frosted.
  - `sky-*` = the soft blue companion (gradients/orbs only — Azure stays the interactive colour). Shadow tokens: `--shadow-soft/float/glow`.
  - `AssessmentRing` arc = a blue→azure `<linearGradient>` stroke with a drop-shadow glow.
  - `SiteFooter` background is `--footer-gradient` (deep navy-blue → teal); its icon strip sits in a dark glass panel.
- Motion stays quiet (fade+rise reveal, 250ms glass hover-lift) except the Assessment Ring arc-fill.
- **Entrance motion (owner request, Aug 2026)** — two layers, both no-op under `prefers-reduced-motion`:
  - **Route-in:** `PageReveal` (`src/components/marketing/PageReveal.tsx`) wraps `<Outlet/>` in `RootLayout`; keyed by `location.pathname` so it replays on every navigation (a same-page hash nav like `/#how-it-works` does **not** re-trigger it). Fade + 12px rise, ~450ms.
  - **Scroll-in:** `Reveal` (fade + 10px rise via IntersectionObserver, one-shot). `Section` now self-reveals its content by default (`reveal` prop, default `true`) — future `<Section>` gets it free. The homepage sections + condition landing pages already choreograph their own children with `Reveal` (heading, then staggered card grids), so **they pass `reveal={false}`** to avoid a doubled rise. The other content pages — `LegalPage`, `FaqPage`, `CostsPage`, assessment `ResultPage` — now wrap their top-level blocks in `Reveal` directly. Dashboard / shop / cart / checkout / login stay static (short, form-heavy, some behind auth).
- **Dark mode — REMOVED (stakeholder + owner decision, Sept 2026).** There was a full wired dark theme (Aug 2026): `.dark` on `<html>`, a `src/theme/` `useSyncExternalStore` store, a pre-paint script in `index.html`, a footer + dashboard-profile `ThemeToggle`, a large `.dark {}` token block in `index.css`, `~80` `dark:` utility classes, and three client-feedback tuning passes (ground → near-black teal, accent-depth, contrast QA). A stakeholder review found the dark ground too dark / accent text too murky ("olive on dark, hard to read"); after weighing a contrast-fix pass vs. removal, the owner chose **remove it entirely, light-only**. Gone now: `src/theme/`, `ThemeToggle.tsx`, the inline script, `@custom-variant dark` + the `.dark {}` block + `:is(.dark *)` rules in `index.css` (`color-scheme` is `light` only), `common:theme.*` and `dashboard:profile.{appearance,theme}` strings, and every `dark:` utility class across the 20 component files. `Logo`'s `inverse` prop stays (explicit white artwork for the dark footer) but no longer auto-detects a theme. The dashboard Profile "Appearance" group is now just the language row. Do **not** re-add a dark theme without a new owner decision. (Full removal history is in git — commit range around this note.)
- `AssessmentRing` tones: `brand` (default) · `mint` · `deep`. `Section` tones: `surface` (transparent) · `raised` (faint frosted band) · `brand` (blue-teal gradient) · `mint` (mint wash).

## UX polish + PO commerce/legal ratification (2026-09-04)

A session of checkout/fulfilment UX work (Baymard-benchmarked) followed by a **14-point Product Owner ratification** governing commerce, fulfilment and legal data. The overarching rule: **WeCare must never present operational certainty that does not yet exist** — company identity, delivery coverage, prices, tracking, support hours, COAs, legal dates. **These notes supersede earlier descriptions where they conflict.**

### Mobile / layout polish
- **Single-button rows are `w-full sm:w-auto` on mobile** across the app (standalone primary actions on cart/checkout/confirmation, conditions, FAQ, costs, contact, age gate, exclusion step, review status, dashboard, consent banner, `PostcodeStep`, dashboard Support "Get in touch" + Orders "Complete order"). Small inline `size="sm"` controls (e.g. Profile "Change photo") and deliberate multi-control rows (assessment "Next" sharing its row with "Start over") are exempt.
- **`NextSteps`** (`src/components/marketing/NextSteps.tsx`) is now **always a vertical single-column list** — the old `sm:grid-cols-3` crushed the steps in narrow containers (the checkout summary aside, the confirmation `max-w-md` box).
- **`SolutionMark` medallion variant restyled** — crisp near-white tile (`from-white to-sage-50/70`), hairline `ring-petrol-200/70`, a soft **teal-tinted** lift shadow (brand colour, not grey), glyph up to `size-1/2` / `strokeWidth 1.75`; `image-glow` dropped. `ShopIndexPage` cards give it a tinted "well" (`from-sage-100/70 to-petrol-50/50`, inset hairline, `aspect-[5/3]`).
- **`HowItWorksPage`** (`/so-funktioniert-wecare`): the old full-bleed `Section tone="brand"` CTA card with an `AssessmentRing` decoration was removed; the page now ends with a plain `w-full sm:w-auto` "Start free assessment" button in the content column. `howItWorksPage.ctaHeading` is unused.
- **Support dashboard hero**: medallion + intro text are a `flex` row (was stacked).

### Checkout / fulfilment UX (Baymard)
- **`CheckoutPage` form**: separate **First name / Last name** (PO #5 — canonical fields for the medical/pharmacy/invoicing chain, *not* a merged "Full name"), controlled inputs, per-field `autocomplete` / `inputmode` / `autocapitalize` / `autocorrect="off"` / `spellcheck={false}`, `maxlength={4}` on postcode. **Inline validation on blur** with adaptive `checkout.errors.*` messages (Austrian postcode checked via `AT_POSTCODE_RE`), `aria-invalid` + `aria-describedby`, `role="alert"`, focus jumps to the first error on submit. **Optional phone** field (`checkout.fields.phoneHint` "For delivery updates, if available") prefilled from the profile — PO #4: conditionally required only when a real carrier requires it.
- **Shipping address is captured and stored on the order** (`ShippingAddress` on `Order.shipTo`) and shown on the confirmation page, the dashboard delivery card (replacing the coverage map once an order exists), and the Orders page (hero tile + `postalCode city` sub-line in the desktop table + full block in mobile cards). PO #8: **order metadata is `localStorage` (`wecare.orders`); the address is `sessionStorage`-only (`wecare.order-addresses`), merged on read** — never written to disk. Marked DEV/STAGING ONLY in `orders.ts`; AuthContext clears both on sign-out. Replace with a server-side EU-hosted record before production.
- **`CheckoutSteps`** (`src/components/marketing/CheckoutSteps.tsx`) — a small non-clickable progress bar **Cart → Details → Review**, then **"Complete"** on the confirmation page. Never shows "Confirmed" as a future step. Hidden on the cart when commerce is disabled.
- **`OrderConfirmationPage`** now resolves the full order and shows: line items + thumbnails, order total, **payment method**, delivery address (+ phone), a stage-based `confirmation.timingNote` (PO #12 — **no invented delivery date**), a support-contact line, and a primary CTA **"View order status"** (PO #6 — *not* "Track your order"; there is no carrier tracking).
- **Payment abstraction** (PO #9): `src/features/payments/payments.ts` — `PAYMENT_METHODS` with per-method `enabled` (card/sepa/klarna present but off), `ENABLED_PAYMENT_METHODS`, a no-op `requestPayment()`. **No PSP is integrated**; D7 (invoice / bank transfer, settled offline after approval) stands. Checkout renders the radio list from `ENABLED_PAYMENT_METHODS`.

### Commercial checkout is DISABLED until real prices (PO #11 — HARD PRODUCTION BLOCKER)
- **`COMMERCE_ENABLED` in `src/config.ts`** = `PRICES_CONFIRMED` (no dev bypass — the app behaves in dev exactly as in production). While off:
  - `CartPage` shows `cart.finalPriceNote` ("The final price will be shown before you confirm your order.") instead of subtotal/total, and no checkout CTA.
  - `CheckoutPage` (if reached) shows a `checkoutUnavailable.*` panel — no form, no "Place order".
  - The Orders **pending-cart hero** hides prices + points at `/dashboard/recommendation`.
  - `ProductPage`: for an approved review it shows `solution.orderingDisabledNote` instead of the gram selector + "Add to cart".
  - `analytics` `checkout_started` fires only when the form will actually render (past the commerce + review-approval gates).
- The gate applies everywhere — dev and production alike. To exercise the full checkout locally, set `PRICES_CONFIRMED = true` in `src/config.ts` temporarily. It opens for real when pharmacy prices land.
